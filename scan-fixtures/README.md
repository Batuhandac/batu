# Scan Fixtures

Use this folder to measure exact-print scan accuracy.

Each fixture should be a JSON file with this shape:

```json
{
  "id": "pokemon-base1-4-charizard-front-001",
  "image": "./images/pokemon-base1-4-charizard-front-001.jpg",
  "expected": {
    "game": "pokemon",
    "name": "Charizard",
    "setCode": "base1",
    "setName": "Base Set",
    "number": "4",
    "rarity": "Rare Holo",
    "finish": "holofoil"
  },
  "actual": {
    "game": "pokemon",
    "name": "Charizard",
    "setCode": "base1",
    "setName": "Base Set",
    "number": "4",
    "rarity": "Rare Holo",
    "confidence": 0.98
  },
  "status": "verified",
  "notes": "Optional notes about glare, sleeve, language, slab, crop, or provider."
}
```

`actual` can be filled manually after a scan export, or generated by the automated benchmark runner.

Run fixture validation:

```sh
npm run scan:verify
```

Run a live provider benchmark against known Pokemon TCG API card images:

```sh
npm run scan:bench:pokemon -- --set=base1 --limit=25
```

Run across multiple eras:

```sh
npm run scan:bench:pokemon -- --sets=base1,jungle,fossil,swsh12,sv3pt5,sv8 --limit=120
```

This consumes roughly one GiblTCG scan credit per card. Use it before each TestFlight build and keep generated JSON reports under `scan-fixtures/reports/` while tuning the scanner.

Accuracy policy:
- `verified`: exact physical printing matches.
- `needs_review`: system produced likely alternatives but did not auto-accept.
- `unidentified`: no safe match.
- `wrong`: system selected the wrong exact printing.

Launch rule: `wrong` must be zero before one-tap add is enabled for a game.
